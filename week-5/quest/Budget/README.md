# 가계부 — 카테고리별 합계

수입·지출을 기록하고 **카테고리별로 얼마를 썼는지** 한눈에 보는 앱입니다.

![카테고리별 합계](가계부%2001%20카테고리별%20합계.png)

- 프론트엔드: 빌드 도구 없는 단일 `index.html` (CDN React 18 · Babel Standalone · Tailwind)
- 백엔드: 단일 `server.js` (Express 5)
- DB: Supabase PostgreSQL (`pg`, Transaction Pooler 6543) — 테이블 접두사 `budget_`

## 화면

| 화면 | 내용 |
|---|---|
| `#/` 카테고리별 합계 | 도넛 + 비율 막대. 막대를 누르면 그 카테고리 내역으로 넘어갑니다 |
| `#/monthly` 월별 집계 | 수입·지출 막대 차트 + 월별 집계표 + 카테고리 × 월 교차표 |
| `#/entries` 거래 내역 | 날짜별 묶음 + 그날의 순증감. 오른쪽에서 바로 추가 |
| `#/categories` 카테고리 관리 | 추가·삭제. 거래가 있는 카테고리는 삭제가 막힙니다 |

![월별 집계](가계부%2004%20월별%20집계.png)

![거래 내역](가계부%2002%20거래%20내역.png)

## 실행

```powershell
cd week-5\quest
npm install
Copy-Item .env.example .env     # DATABASE_URL 을 실제 값으로 채웁니다
node server.js                   # http://localhost:3000
```

첫 요청이 들어올 때 테이블이 자동으로 만들어지고, **비어 있을 때만** 샘플 데이터가 들어갑니다.
스키마와 시드만 먼저 만들어 두려면:

```powershell
node server.js --seed
```

## API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/summary?month=YYYY-MM` | **카테고리별 합계** (월 생략 시 전체 기간) |
| GET | `/api/monthly?limit=N` | **월별 집계** — 월 합계 + 카테고리 × 월 격자 (기본 24개월, 최대 60) |
| GET | `/api/entries?month=&kind=&categoryId=` | 거래 목록 |
| POST | `/api/entries` | 거래 추가 `{ categoryId, amount, memo?, spentOn }` |
| PATCH | `/api/entries/:id` | 거래 수정 (보낸 필드만) |
| DELETE | `/api/entries/:id` | 거래 삭제 |
| GET | `/api/categories` | 카테고리 목록 |
| POST | `/api/categories` | 카테고리 추가 `{ name, kind, emoji?, color? }` |
| DELETE | `/api/categories/:id` | 카테고리 삭제 (거래가 있으면 409) |
| GET | `/api/months` | 거래가 있는 월 목록 |
| GET | `/api/health` | 헬스체크 (DB 연결 포함) |

응답은 전부 `{ success: true, data }` 또는 `{ success: false, message }` 입니다.


```json

  ]

```

## 테이블

```sql
budget_categories (id, name, emoji, kind, color, created_at)   -- UNIQUE (kind, name)
budget_entries    (id, category_id→, amount, memo, spent_on, created_at)
```

`kind` 는 `'expense' | 'income'`. Supabase 한 곳을 여러 과제가 공유하므로 접두사 `budget_` 을 붙였습니다.

## 구현하면서 해결한 문제

### 합계를 어디서 계산할까 — 브라우저가 아니라 DB에서

거래를 전부 내려받아 화면에서 `reduce` 로 더하는 게 제일 쉽지만, 그러면 거래가 쌓일수록
네트워크로 오는 양이 같이 늘어납니다. `GROUP BY` 로 DB에서 끝내면 **내려오는 양이
카테고리 수만큼으로 고정**됩니다. 1년치를 보든 하루치를 보든 응답 크기가 같습니다.

검증할 때 거래를 직접 더한 값과 서버 합계가 일치하는지 확인했습니다
(`지출 955,500 = 955,500`, 카테고리별로도 전부 일치).

### 거래가 없는 카테고리를 0원으로 보여주려면 조건이 `ON` 절에 가야 한다

"이번 달에 교육비를 안 썼다"도 정보라서 0원 카테고리를 보여주고 싶었습니다.
그러려면 `LEFT JOIN` 인데, 월 조건을 습관대로 `WHERE` 에 두면 거래 없는 쪽은
`spent_on` 이 `NULL` 이라 조건에서 탈락해 **아예 사라집니다.**

```sql
-- ✗ 거래 없는 카테고리가 사라진다
LEFT JOIN budget_entries e ON e.category_id = c.id
WHERE e.spent_on >= $1::date

-- ✓ 조건을 ON 절로
LEFT JOIN budget_entries e ON e.category_id = c.id
     AND e.spent_on >= $1::date AND e.spent_on < ($1::date + INTERVAL '1 month')
```

### 날짜가 하루 밀리는 문제 — 서버와 브라우저 양쪽에서

`week-4` 에서도 만났던 함정이 양쪽에 다 있었습니다.

- **서버**: `DATE` 를 그대로 내보내면 JS `Date` 가 되면서 KST 자정이 UTC 로 전날이 됩니다.
  → `to_char(spent_on, 'YYYY-MM-DD')` 로 문자열화해서 내보냅니다.
- **브라우저**: 오늘 날짜 기본값을 `new Date().toISOString().slice(0,10)` 으로 만들면
  **오전 9시 이전에 어제 날짜**가 찍힙니다. → 로컬 기준으로 직접 조립합니다.

```js
function todayLocal() {
  const d = new Date();
  const p = (n) => String(n).padStart(2, '0');
  return `${d.getFullYear()}-${p(d.getMonth() + 1)}-${p(d.getDate())}`;
}
```

### 입력 오류가 "DB 연결 실패"로 둔갑했다

테스트 중 `spentOn: "2026-13-99"` 를 보냈더니 **503 "데이터베이스에 연결하지 못했습니다"**
가 돌아왔습니다. 원인은 두 군데였습니다.

1. 날짜 검증이 `/^\d{4}-\d{2}-\d{2}$/` 형식만 봐서 **13월 99일이 통과**했고,
2. 에러 핸들러가 *모든* 5자리 SQLSTATE 를 503으로 묶고 있었습니다.

형식이 맞는 것과 실제 달력에 있는 것은 다릅니다. 달력에 있는 날짜인지까지 확인하고,
503은 **정말 DB에 닿지 못한 경우로만** 좁혔습니다.

```js
// 2026-02-30 같은 값을 걸러낸다 (UTC 로 만들어야 시간대 때문에 밀리지 않는다)
const probe = new Date(Date.UTC(y, m - 1, d));
if (probe.getUTCDate() !== d) throw fail('존재하지 않는 날짜입니다.');

// 08xxx 연결 예외 / 53xxx 자원 부족 / 57Pxx 셧다운 — 이것만 503
const DB_DOWN_SQLSTATE = /^(08|53|57P)/;
```

입력 오류(22xxx)·제약 위반(23xxx)까지 "DB 연결 실패"로 보고하면 원인을 찾을 수 없습니다.

### curl 로 한글을 보내면 깨진다 (앱 버그가 아니었던 것)

중복 카테고리가 409 대신 201을 돌려받아 버그인 줄 알았는데, 원인은 **PowerShell/Git Bash 의
curl 이 한글을 CP949 로 보낸 것**이었습니다. `"식비"` 가 다른 바이트로 전달되니 당연히
중복이 아니었고, DB에는 `"<22><3A><B8>"` 같은 이름의 행이 생겼습니다.

검증 스크립트를 `node` 의 `fetch` 로 바꾸니 409가 정상적으로 나왔습니다.
**Windows에서 한글이 섞인 API를 curl 로 테스트하지 않습니다.**

### 가계부 관행인 녹색/빨강은 쓸 수 없었다

수입은 녹색, 지출은 빨강 — 가계부라면 당연한 선택 같지만 **적록색각이상에서 이 둘은
사실상 같은 색**입니다. 눈대중 대신 색상 대비를 계산해 보니 수치로 나왔습니다.

| 조합 | 적록색각이상 ΔE | 판정 |
|---|---|---|
| 녹색 `#059669` ↔ 빨강 `#e11d48` | **5.8** | ❌ 구분 불가 |
| 파랑 `#2a78d6` ↔ 주황 `#eb6834` | **24.7** | ✅ |

그래서 수입=파랑, 지출=주황으로 갔습니다. 색만으로 정체를 알게 하지 않도록 범례도 항상 둡니다.

교차표의 히트맵도 같은 원칙입니다. 지출 격자는 **주황 한 색의 명도 단계**, 수입 격자는
**파랑 한 색의 명도 단계** — 차트에서 그 계열이 쓰는 색과 일치시킵니다.
*색이 가리키는 대상이 화면마다 달라지면 안 되기 때문입니다.*
무지개 램프를 쓰지 않는 이유이기도 합니다. 크기는 명도가, 정체는 색상이 나타냅니다.

칸 안에 금액이 들어가므로 단계마다 글자색도 계산해서 골랐습니다. 파랑 4번째 단계는
먹색 4.46:1 / 흰색 4.42:1 로 **양쪽 다 4.5:1 에 못 미쳐** 그 단계만 더 어두운 값으로
바꿨습니다(흰 글자 5.39:1).

### 막대 레이블은 '더 큰 쪽'에만 붙인다

수입·지출 두 막대 캡에 값을 모두 붙였더니, 24px 막대 위에 40px 짜리 글자가 둘 나란히 서서
**낮은 쪽 레이블이 옆 막대를 덮었습니다.** 낮은 막대의 캡은 애초에 옆 막대에 가려지는 자리입니다.

그래서 마지막 달의 **더 큰 쪽** — 캡 위가 비어 있는 막대 — 에만 붙이고, 띠가 좁아
글자가 옆 띠까지 번질 때(`bandW < 56`)는 아예 생략합니다.
가려지는 값은 없습니다. 축·범례·툴팁·집계표가 모두 받습니다.

### 축 레이블 간격은 '마지막 달'부터 거꾸로 센다

달이 많아지면 축 글자를 건너뛰며 그려야 하는데, 앞에서부터 세고(`i % n === 0`)
마지막 달만 따로 끼워 넣었더니 **마지막 둘이 바싹 붙어 `9월0월`로 겹쳤습니다.**

기준을 뒤집어 `(개수 - 1 - i) % n === 0` 으로 세니 마지막 달이 항상 기준점이 되어
겹칠 일이 없어졌습니다. 연도 표시도 "바로 앞 달"이 아니라 **"직전에 표시된 달"** 과
비교해야 합니다. 그러지 않으면 해가 바뀌는 달이 건너뛰어진 자리일 때 연도가 아예 안 나옵니다.

### 거래가 없는 달도 0원으로 채워 넣는다

데이터가 있는 달만 쓰면 중간에 비어 있는 달이 사라지면서 **시간축이 왜곡됩니다.**
3월과 6월만 기록이 있을 때 둘이 나란히 붙어 버리면 "연속한 두 달"처럼 보입니다.
가장 이른 달부터 가장 늦은 달까지 빠짐없이 채운 뒤 잘라냅니다.

월평균도 같은 맥락입니다. "거래가 있었던 달"이 아니라 **표에 보이는 달 수**로 나눕니다.
한 푼도 안 쓴 달도 0원을 쓴 달이니까요.

### 달이 두 개뿐일 때 막대가 허허벌판에 떠 보였다

띠 폭을 화면 폭 ÷ 달 수로 잡으니, 2개월일 때 띠 하나가 500px이 되어 24px 막대가
휑하게 떠 보였습니다. 띠 폭에 상한(104px)을 두고 남는 자리를 양옆 여백으로 돌려
가운데로 모았습니다.

### 금액은 `type="number"` 대신 `text` + 서버에서 콤마 제거

`1,000` 처럼 콤마를 섞어 치는 게 자연스러운데 `type="number"` 는 그 입력을 통째로 버립니다.
`text` + `inputMode="numeric"` 으로 받고 서버가 콤마를 지운 뒤 숫자로 바꿉니다.
원 단위라 소수점은 `Math.round` 로 버립니다.

### 거래를 추가한 뒤 합계를 화면에서 더하지 않는다

추가된 금액만 기존 합계에 더하면 빠르지만, 비율·건수·정렬까지 손으로 맞춰야 하고
한 번 어긋나면 서버 집계와 영영 달라집니다. **추가·삭제 후에는 합계를 다시 읽습니다.**
삭제는 체감 속도를 위해 목록만 낙관적으로 먼저 지우고, 실패하면 되돌립니다.

## 배포 (Vercel)

```powershell
npx vercel env add DATABASE_URL production
npx vercel --prod
```

`vercel.json` 이 `/api/*` 는 `server.js` 로, 나머지는 `index.html` 로 보냅니다.
서버리스는 콜드 스타트마다 초기화가 돌 수 있어, 스키마 생성은 플래그와 Promise 를 공유해
중복 실행을 막았습니다.
