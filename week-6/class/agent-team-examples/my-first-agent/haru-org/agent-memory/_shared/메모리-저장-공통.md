# 메모리 저장 공통 룰 — 전 팀장 필수 (클래스 워크스페이스)
갱신: 260913 09:00 (제정)

> 일이 끝나면 **저장하고 퇴근한다.** 저장 안 한 일은 내일 아침 비서실 브리핑에 안 뜬다 = 없던 일.

## 1. 두 군데에 나눠 적는다
| 어디 | 무엇 | 누가 읽나 |
|---|---|---|
| `haru-org/0_지금/<작업명>_YYMMDD/_작업로그.md` **머리 블록** | 작업 상태 (상태·멈춘 지점·다음 할 일·대표님 손) | 비서실 브리핑 · 협조 팀장 |
| `haru-org/agent-memory/<내 팀>/MEMORY.md` | 나의 배움 + **나의 다음 할 일 리마인더** | 나 자신 (다음 호출 때) · 비서실 브리핑 |

- 산출물(리서치 표·글·대문 이미지)은 **작업 폴더**에 파일로. 메모리에 본문 복사 금지.
- 작업로그 머리 형식은 `작업로그-공통.md` §2 그대로.

## 2. MEMORY.md 고정 구조 — 비서실이 이 구조를 읽는다
```
# <이름> — <팀> 메모리
> 갱신: YYMMDD HH:MM

## 내 역할 한 줄
## 노하우 (누적)
## 배움 (최근이 위)
- YYMMDD — <한 줄>
## 다음 할 일
- [ ] YYMMDD <할 일> — <맥락 · 어느 작업 폴더>
```
- `## 다음 할 일`은 **체크박스 + 날짜** 형식 엄수. 비서실이 날짜로 "오늘/내일/지난 것"을 가른다.
- 끝난 건 `- [x]`로 바꾸고, 5개 넘게 쌓이면 지운다.
- `갱신:` 시간까지.

## 3. 저장 순서 (일 끝낼 때마다)
1. 산출물 파일 저장 (작업 폴더)
2. `_작업로그.md` 머리 갱신 (상태 4종 중 하나, 갱신 시각)
3. `MEMORY.md` — 배움 1줄 이상 + 다음 할 일 갱신
4. 30분짜리 단발 일이 남으면 `haru-org/workspace/0-ing/haru-할일.md`에 한 줄
5. 보고 마지막 줄: `🗂 저장: 작업로그 ○ / 메모리 ○ / 할일 ○(또는 —)`

## 4. 금지
- 메모리에 "오늘 뭐 했다" 일기 쓰기 (→ 작업로그)
- 날짜 없는 다음 할 일
- 다른 팀 메모리 편집 (협조 사항은 작업로그 머리 `협조:`에)
