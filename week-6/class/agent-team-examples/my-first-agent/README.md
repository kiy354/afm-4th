# 내 첫 직원 만들기 — 팀 kit와 같은 형식으로

> 25~30분 · VS Code + Claude 확장 · 터미널 없음
> 7인 팀 kit(`haru-agents-agent-format`)를 열기 **전에** 한다. 여기서 만든 직원은 그 팀에 파일 복사만으로 합류한다.

**직원 한 명 = `.claude/agents/<이름>.md` 한 장.** 팀 kit의 팀장 7명도 전부 이 한 장짜리 파일이다. 형식이 같으면 —
- kit를 열었을 때 7장이 다 읽힌다 — 내가 쓴 것과 같은 칸
- 내 직원을 kit에 넣으면 비서실이 **알아서** 브리핑에 띄운다 — 메모리·작업로그를 같은 자리에 쓰니까
- 두 번째 직원은 복사 → 이름·절차·금지만 바꾸면 끝

## 이 폴더
| 파일 | 무엇 | 언제 |
|---|---|---|
| `README.md` | 이 순서표 | 지금 |
| `따라하기.md` | **빈 폴더에서** 이 구조를 처음부터 만드는 순서 (내 브랜드용) | 이 폴더로 한 번 해 본 뒤 |
| `.claude/agents/리뷰담당.md` | **예시 직원** 완성본 — 오하늘, 리뷰담당 | §1 부려보기 · §2 해부 |
| `직원-템플릿.md` | 빈 틀 + 7칸 채우는 법 | §3 |
| `채용공고.md` | 붙여넣기 지시문 (예시 + 내 것 빈칸) | §3 |
| `haru-org/agent-memory/리뷰담당/MEMORY.md` | 예시 직원의 메모리 — 입사 첫날 상태 | §1 저장 확인 |
| `haru-org/agent-memory/_shared/` | 공통 룰 3 (보고·작업로그·메모리 저장) — kit와 **같은 파일** | 직원이 읽음 |
| `haru-org/memory/haru-팩트시트.md` | 제품명·가격·용어 — kit와 같은 파일 | 직원이 읽음 |
| `haru-org/_fixtures/reviews-수건.csv` | 리뷰 54건 (⚠️ 데모) — 예시 직원의 일감 | §1 |

| `_예시결과_260920/` | 강사 리허설 결과 — 보고 · 작업로그 · 저장 후 메모리. "이렇게 나오면 성공" | §1 비교용 |

폴더 구조와 파일 이름이 kit와 같다. `.claude/agents/` = 역할(누가 무엇을 어떻게) · `haru-org/` = 지식·상태(무엇을 아는가·어디까지 했나).

## 1. 예시 직원 먼저 부려보기 (5분)
1. VS Code → **File → Open Folder** → 이 폴더 → "신뢰"
2. Claude 아이콘 → 그대로 입력:
```
리뷰담당 리뷰 정리
```
3. 보는 포인트
   - 숫자마다 **분모** (리뷰 54건 · 기간 · 파일명) — 센 것만 말한다
   - 불만 TOP3에 **원문 인용 + 리뷰 번호** — 토씨 그대로
   - "~해야 한다"가 없다 — **옵션 정렬까지, 결정은 대표님**
4. 저장 확인 — 탐색기에서
   - `haru-org/0_지금/리뷰정리_YYMMDD/` — `_작업로그.md` 머리 블록 + 결과 파일
   - `haru-org/agent-memory/리뷰담당/MEMORY.md` — `## 배움`에 오늘 한 줄 · `## 다음 할 일`에 날짜 붙은 줄

   이 두 군데가 채워졌으면 성공. **저장 안 한 일은 내일 없는 일** — kit의 비서실은 이 두 파일만 읽는다.

빠른 분 — `리뷰담당 불만만` · `리뷰담당 스마트스토어` · `리뷰담당 메모 유연제 언급은 채널별로 세어 둘 것`

## 2. 직원 파일 해부 (5분) — 7칸
`.claude/agents/리뷰담당.md`를 열고 7칸을 찾는다. kit의 팀장 7명도 이 7칸이다.

| 칸 | 파일 어디 | 무엇 | 워크시트에서 |
|---|---|---|---|
| ① 이름 | `name:` = 파일명 | 부르는 말. 문장 앞에 쓰면 그 직원이 **옆방**에서 일하고 결과만 가져온다 | — |
| ② 언제 부르나 | `description:` | 어떤 요청이 오면 넘길지. Claude가 이 문장만 보고 **알아서** 위임한다 — 요청 예를 구체적으로 | STEP 1 |
| ③ 도구 | `tools:` | 손에 쥐어주는 것. 읽기만이면 `Read, Glob, Grep` · 파일을 만들면 `Write, Edit` · 세거나 날짜 계산은 `Bash` | STEP 4 |
| ④ 읽는 파일 | 시작할 때 반드시 읽기 | 자기 메모리 → 기준 파일(팩트시트·가이드) → 공통 룰 2 | STEP 3 ⓐ |
| ⑤ 모드·절차·출력 | 모드 표 · A-1~A-3 | 무엇을 · 무엇을 보고 · 무엇이 나오면 끝. 기본 모드 하나는 인자 없이 돈다 | STEP 2·3·5 |
| ⑥ 저장 | A-4 | 작업로그 머리 + MEMORY 배움 1줄·다음 할 일 — 비서실이 읽는 자리 | — |
| ⑦ 룰 | 룰 | 금지 3 이상 + "판정은 대표님" | STEP 4 확인·내가 |

- ①②③은 맨 위 `---` 사이(frontmatter). 규격은 이 셋 + `model: inherit`(대화와 같은 모델)뿐. 나머지는 전부 **말로 쓴 지시**다.
- 금지 규칙이 직원을 만든다 — 지어내기 ❌ · 원본 수정 ❌ · 밖으로 내보내기 ❌. **나가는 것 · 못 되돌리는 것 = 사람 몫.**

## 3. 내 직원 만들기 (10분)
워크시트에서 고른 일 하나(STEP 1)를 가져온다. 일감 파일이 있으면 `haru-org/_fixtures/`에 넣는다 (CSV·xlsx·md · **개인정보 지운 것**). 없으면 리뷰 CSV로 연습해도 된다.

**길 A — 채용 공고 붙여넣기** (권장)
1. `채용공고.md` 아래쪽 빈칸을 채운다 — STEP 5의 무엇을·무엇을 보고·무엇이 나오면 끝 + STEP 4의 금지
2. 채운 공고를 통째로 Claude에 붙여넣는다 → `.claude/agents/<이름>.md` + `agent-memory/<이름>/MEMORY.md`가 생긴다
3. "파일 만들까요?" → 예. 만든 뒤:
```
<이름> 직원 파일 보여줘
```
4. 7칸 체크 — 비어 있거나 `{{`가 남았으면 그 칸만 고쳐 달라고 한다: `<이름> 직원 파일 룰에 "원본 수정 금지" 추가해줘`

**길 B — 직접 쓰기**: `직원-템플릿.md`의 틀을 `.claude/agents/<이름>.md`로 복사해 `{{ }}`를 채운다. 메모리는 `agent-memory/리뷰담당/MEMORY.md`를 복사해 이름만 바꾼다.

이름 규칙: 파일명 = `name:` = 부르는 말. kit처럼 한글 팀 이름(`리뷰담당`) 또는 영문 소문자·하이픈(`review-desk`). 띄어쓰기·특수문자 없이. **템플릿은 `.claude/agents/` 안에 두지 않는다** — 그 폴더의 파일은 전부 직원으로 읽힌다.

## 4. 첫 업무 → 검토 → 규칙 한 줄 (5분)
```
<이름> <기본 호출어>
```
결과가 오면 **검토는 나**. 이상한 해석·없는 숫자·판정 문장이 보이면:
```
<이름> 직원 파일 룰에 "<고칠 규칙 한 줄>" 추가하고 다시 해줘
```
한 번에 잘 안 나온다. 고친 규칙은 파일에 남으니 **다음부터는 한마디**.

## 5. 진짜 남았나 (2분)
```
/clear
<이름> <기본 호출어>
```
대화를 지워도 같은 여는 말·같은 표가 나오면 — 직원은 채팅이 아니라 **파일**이다. `MEMORY.md`에 §4의 배움이 남아 있으면 기억도 파일이다.

## 6. 팀에 합류시키기 (kit 받은 뒤 · 5분)
kit 폴더를 연 뒤, 이 폴더의 세 가지를 kit의 **같은 자리**에 복사한다.

| 이 폴더 | → kit |
|---|---|
| `.claude/agents/<이름>.md` | `.claude/agents/` |
| `haru-org/agent-memory/<이름>/` | `haru-org/agent-memory/` |
| `haru-org/_fixtures/<내 일감 파일>` | `haru-org/_fixtures/` |
| (선택) `haru-org/0_지금/<작업>_YYMMDD/` | `haru-org/0_지금/` — 작업 이력까지 데려가려면 |

그리고 kit에서:
```
haru-org/조직도.md 표에 <이름> 직원 한 줄 추가해줘 — 대표 직속 (이 폴더 조직도.md의 줄을 그대로)
비서실
```
브리핑 ③ 대표 직속에 내 직원의 `다음 할 일`이 뜨면 **합류 완료.** 비서실은 `agent-memory/*/MEMORY.md`와 `0_지금/*/_작업로그.md`를 전부 읽는다 — 같은 자리에 같은 구조로 썼기 때문에 따로 연결할 게 없다.

## 막히면
| 증상 | 처방 |
|---|---|
| 이름을 불러도 본인이 그냥 함 (여는 말이 안 나옴) | `description:`이 흐림 — 요청 예를 구체적으로. 급하면 "리뷰담당 **에이전트로** 리뷰 정리" |
| "파일이 없다"고 함 | 압축 푼 **이 폴더**를 Open Folder 했는지 · `.claude`와 `haru-org`가 같은 폴더인지 |
| 숫자가 파일과 다름 | A-1 "숫자는 명령 결과에서만"이 있는지 · `Bash`가 `tools:`에 있는지 |
| 저장을 안 함 | A-4 저장이 "필수"로 있는지 · `Write, Edit`가 `tools:`에 있는지 |
| 직원이 되묻기만 함 | A-1에 "묻지 않고 찾는다 · 없으면 '없음'" 추가 |
| 그 외 | 이 폴더에서 Claude에게: "뭐가 문제인지 네가 진단해줘" |

## 빠른 분 — 두 번째 직원
kit의 데모 세계엔 **빈자리**가 하나 심어져 있다. 부티크 호텔의 수건 500장 B2B 견적 문의가 "담당 없음"으로 멈춰 있다 (`_fixtures/gmail-inbox.md` · `agent-memory/경영/MEMORY.md`). `견적담당` 직원을 만들어 팩트시트 가격으로 견적 옵션표 + 회신 초안까지 (발송·단가 결정은 대표님) — 채용 공고 빈칸에 이 일을 넣으면 된다.
